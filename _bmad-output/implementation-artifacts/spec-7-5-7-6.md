# Stories 7.5 and 7.6: inbox, unread state, continuity (BE+FE)

Acceptance criteria: `epics.md`, Epic 7. Rules: FR-50, FR-51, FR-53, AD-13.

## API

| Route | Meaning |
|---|---|
| `GET /api/v1/conversations?cursor=` | the caller's inbox, latest activity first, 20 a page (`results`, `next`) |
| `GET /api/v1/conversations?listing_id=` | unchanged (Story 7.1) |
| `GET /api/v1/conversations/unread-count` | `{unread}`: Conversations with unread Messages |
| `POST /api/v1/conversations/{id}/read` `{seq}` | read up to `seq`; never goes back; 204 |

Every Conversation payload gains `unread_count`.

## Decisions

- Unread is `last_seq - <my read_seq>` (sending marks one's own thread read), so no Message query.
  No migration: the columns exist since 7.1.
- Reading Messages does not mark them read; the page says so with `POST .../read` while visible.
- The inbox takes a fixed number of queries for any number of Conversations
  (`identity.participants`, `listings.listing_headers`).
- No Message text in the inbox (and none in logs). Rows show the Listing header, the other
  participant, last activity and the unread count.
- 7.6: read-only rules and header labels were built in 7.1. Added: tests of history staying readable,
  and a clearer refusal for a suspended account.
- History and resume: `GET .../messages?after=` (7.1, 7.3), unchanged.
- Frontend: `/messages` inbox, refreshed by `message.created`; header "Messages" link with the count,
  read on sign-in, navigation, focus and after marking read (no socket in the header). Not shown to
  administrators. UI polish deferred.

## Review

Security review of messaging: no medium-or-higher findings. Accepted minor items: after "Load more" a row pushed off page 1 can be missing until reload; replying marks unseen incoming messages as read.
