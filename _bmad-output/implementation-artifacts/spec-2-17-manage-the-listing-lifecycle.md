## Intent

**Problem:** Once published, a Listing can only sit there. Owners need to keep it up to date, withdraw it, mark it sold or rented, and see all their Listings grouped by status.

**Approach:** Backend: the full status set (draft, published, archived, sold, rented, removed), a transition service (published to archived/sold/rented, sold/rented to archived; never to published), editing of Published and Archived Listings under the publication rules with identity fields locked while Published, owner visibility of every own status including restricted/removed with a reason, a status counts endpoint, and the Suspended-owner limits. Frontend: My listings grouped by status with counts, the Listing page editable per status with Archive / Mark sold / Mark rented actions. No quota is consumed by any of this; republication (2.18), the one-time correction (2.19) and moderation setting `restricted`/`removed` (2.21 and later) are out of scope except for the read side. Backend first and merged, then frontend. Workflow: narrow local runs (`docs/testing.md`), full suites in CI; decide ambiguities yourself with the best option and report them.

## Boundaries & Constraints

**Always (backend):**
- **Statuses**: `ListingStatus` gains `ARCHIVED`, `SOLD`, `RENTED`, `REMOVED` (migration updating any status CHECK/choices and indexes that mention statuses; existing rows unaffected). Only `listings.publication` may set `published` (unchanged AD-7 guard; extend the AST single-writer guard so that the new status module may write exactly archived/sold/rented and never published/removed; `removed` is written by nobody in this story, it exists for the moderation story and fixtures). The owner-visible set (`policy.OWNER_VISIBLE_STATUSES`) becomes all six statuses; public visibility is unchanged (published and not restricted and owner eligible): archived, sold, rented, removed, draft are never public (test each through `public_listing` and the public image route).
- **Transitions** (`listings/status.py`, new, actor first): `change_status(actor, listing_id, base_revision, target)` with the allowed table published to archived|sold|rented and sold|rented to archived; everything else (including any move to `published` or `removed`, same-status, or from draft/archived/removed) is `409 conflict` with nothing written. One transaction: lock the account then the Listing, compare `base_revision` (`409 stale_revision` with the owner's `current`), check the transition, write status, bump `revision` (revision row recording the status change without content), audit `listing.status_changed` (from and to, ids only), emit domain event `listing.status_changed` (listing id, account id, new status) after commit. No quota, no `PublicationEvent`, no idempotency key needed (a repeat is a clean `409 conflict`). Archive is the only owner "withdraw" action; there is no un-archive here (republication is Story 2.18). Account states: Active and Email-unverified may archive, mark sold and mark rented; a Suspended owner may only archive (sold/rented refused `forbidden`); Deactivated has no session. Capability matrix updated in `docs/account-states.md`/`authorisation-matrix.md`. Non-owner, administrator, Visitor: the same 404/404/401 as other owner routes. A restricted Listing (`restricted` true) or a removed one cannot be changed by the owner (`403 forbidden`, nothing written), archive included for a restricted one? Decide the safest reading (a restricted Listing may still be archived by its owner, a removed one may not) and document it.
- **Editing (`apply_updates`)**: `EDITABLE_STATUSES` becomes draft, published and archived (sold, rented, removed and restricted Listings are refused `forbidden`, view only). Capability `edit_drafts` rules stay (Suspended and Deactivated refused). Identity fields, taken from the registry (`quota_identity` plus any field the registry marks as identity; at minimum purpose, category, subtype, city, locality, area value, area unit and the marla/price-basis items tied to area; derive the set from the registry flag and make the flag cover exactly the spec list, with a registry version bump, `fields.lock` update and `RESPONSE_SHAPE_VERSION` bump only if the wire changes) are rejected with the existing code `not_editable` on that field while the Listing is Published; they are editable while Draft and Archived. A Published edit runs the same completeness rules as publication on the result (reuse `publication.problems_of` or its shared core; no copy): an edit that would leave it invalid (clearing the title, price, bedrooms of a House, the last image, setting a locality outside the city) is refused `400 validation_error` naming each item, nothing written, revision unchanged. An Archived edit is validated field by field like a Draft edit (completeness is enforced again at republication). Edits to a Published Listing consume no quota, write no `PublicationEvent`, bump the revision with a revision row as today, and emit `listing.model_inputs_changed` when a `valuation_input` field changed (existing event). The same status rules apply to images: upload, remove, reorder and cover change are allowed for Published and Archived Listings (cap and cover rules as today) with the extra rule that a Published Listing can never lose its last image (`images_required` style refusal, nothing changed). The public projection and public image routes reflect committed edits immediately (cache lag as documented).
- **Owner visibility of restricted/removed**: add nullable `restriction_reason` (short plain text, max 200, set only by a later moderation story; nothing in this story writes it except test fixtures through a clearly named test helper) to the Listing and expose in the owner resource as `restriction_reason` (null normally) together with the existing `restricted` boolean (add it to the owner Listing resource and serializer if it is not there). The owner can read a restricted or removed Listing (`GET /api/v1/listings/{id}`, My listings, preview where allowed) but not edit it. Removed Listings appear in My listings under removed. The reason text is shown to the owner only and never in public shapes (test).
- **Listing and counts endpoints**: the owner list `GET /api/v1/me/listings` gains/keeps a `status` filter accepting each of the six statuses (invalid value `400`), default order newest first with the cursor pagination of today; add `GET /api/v1/me/listings/counts` returning `{"draft":n,"published":n,"archived":n,"sold":n,"rented":n,"removed":n}` for the caller only (`no-store`, same owner/guard rules as the list). New route `POST /api/v1/listings/{id}/status` with body `{base_revision, status}` (`status` one of archived|sold|rented; anything else `400 validation_error`), CSRF, owner only, `200` owner Listing resource, `no-store`; documented responses 200/400/401/403/404/409. Regenerate `openapi.yaml`, `docs/authorisation-matrix.md`; update `docs/listings.md` (lifecycle table, edit rules, identity fields, Suspended limits), `docs/visibility.md`, `docs/account-states.md`.
- **Interactions to verify with tests**: Draft deletion (2.13) still deletes only drafts (a published/archived/sold listing: `409 conflict` as today); retention jobs and the open-draft cap count only drafts (archived/sold/rented/removed do not count toward the 20 drafts and are never expired by `draft_notice/expiry`); publication of a non-draft is still `409 conflict`; the sample data command still works (it publishes drafts; `--reset` must be able to remove listings in every status through `remove_sample_listing`); the preview endpoint is allowed for the owner's draft and published listing and for the other owner-visible statuses only if the projection can be built (decide: allow for archived/sold/rented/removed with the same projection; document). `listing.status_changed` emitted exactly once after commit, nothing inside the transaction beyond the audit write.
- **Tests (narrow runs)**: every transition in the table and every forbidden one (parametrised matrix), stale revision, non-owner/admin/Visitor, Suspended (view, archive ok, sold/rented/edit refused), Email-unverified, restricted and removed behaviour, published edit of each non-identity field kind (text, money, decimal, enum, amenities map, location text, private address stays private, images) succeeding and consuming no quota (allowance unchanged, no event row), identity field edits refused with `not_editable` while Published but allowed on Draft/Archived, an edit that would make a Published Listing invalid refused with all errors at once and nothing written, last-image protection, valuation event on a valuation_input change and not otherwise, archived edit freedom, public projection after edit/archive/sold (archived/sold/rented vanish from the public projection and public image route), owner list status filter and counts (including for a Suspended owner and per-account isolation), concurrency (two status changes racing, an edit racing an archive: one wins cleanly), fault injection (a failing audit write leaves status/revision unchanged), the AST single-writer guard allowing exactly the intended writers. Lessons from earlier stories apply (static messages, whole-body checks, low-entropy fake words, mutation-check the transition table and the identity lock).

**Always (frontend, after the backend is merged and `npm run api:sync`):**
- **My listings** (`/account/listings`): status tabs (an accessible tablist or a radio group with live counts from the counts endpoint) for Draft, Published, Archived, Sold, Rented and Removed; each tab lists that status with the existing cursor "load more", empty state per tab, counts update after actions, tab choice kept in the URL query (`?status=`) so back/forward and reload keep it; the default tab is the first non-empty in the order Published, Draft, Archived, Sold, Rented, Removed. Rows keep the open link and Preview link and show the status text.
- **Listing page** (`/account/listings/[id]`): the page title and sections adapt to status. Published: the editor works with identity controls (purpose/category/subtype are already fixed; city, locality, area value, area unit and any other registry identity field) read-only with a visible note "These details cannot be changed while the listing is published." (use the registry's identity flag from the registry response, never a hard-coded list); validation errors from a refused edit show next to fields and in the summary like Publish does (including `not_editable` for a stale form); Archived: everything editable, with a note that identity changes are re-checked when it is published again; Sold, Rented, Removed and restricted: read-only view with the reason for restricted/removed shown, no Save, no image actions, no Delete, no Publish. Actions section: Published shows "Archive", "Mark as sold", "Mark as rented" (Suspended owners only Archive; unverified owners all three), Sold/Rented show "Archive", Archived shows none (republish arrives with 2.18, show a short note "Republishing is coming soon" only if it does not mislead; otherwise nothing). Each action opens the accessible confirmation dialog pattern from Story 2.13 (focus trap, Escape, return focus, plain wording of the consequence: archive removes it from public view; sold/rented removes it from public view and records the outcome), sends `POST .../status` with CSRF and the current `base_revision`, handles `409 stale_revision` (existing conflict flow), `409 conflict` (refetch and explain), 403/404 and network failure with Retry, locks save/images/other actions while running (reuse `image-lock.ts` and the publish/delete locking), announces success politely and updates the page and the counts. The Publish section stays draft-only; the 2.13 "no longer a draft" read-only note is replaced by the per-status behaviour above (keep the same test ids where they still apply). Stub backend updated to model statuses, the transition table, edit rules (identity lock, validity on published edit, last image), counts, status filter, Suspended limits; error sentences mirror table updated if the backend adds sentences (read `apps/kernel/errors.py`). Specs: status tabs, counts, URL state, every action and refusal, published edit with identity read-only and a refused invalid edit, archived edit, read-only statuses with reason, Suspended, axe at desktop and mobile in the key states (tabs, published editor, confirmation dialog, read-only statuses), README, prod check only if a proxy behaviour is relied on. Existing specs that visit My listings or the Listing page must still pass (listings, listing-edit, listing-images, listing-preview-delete, listing-publish, listing-location, listing-amenities, listing-terms, publication-allowance, notifications, sign-in).

**Never:** set `published` anywhere but `listings.publication`; consume quota or write a `PublicationEvent` for an edit or a status change; let the owner edit sold, rented, removed or restricted Listings; expose `restriction_reason` or non-public statuses in any public shape; leave an invalid Published Listing after an edit; hard-code the identity field list in the frontend; add Claude attribution to commits.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| Archive / sold / rented a Published listing | owner, fresh revision | `200`, status changed, revision +1, event after commit, not public any more | N/A |
| Sold or rented to archived | owner | `200` | N/A |
| Forbidden transitions | draft/archived/removed source, same status, target published/removed | `409 conflict`, nothing written | envelope |
| Suspended owner | archive / sold / edit | archive `200`, sold and edit refused `403` | envelope |
| Edit non-identity field of Published | owner PATCH | saved, no quota, valuation event if applicable | N/A |
| Edit identity field of Published | city, locality, area... | `400` `not_editable` on that field, nothing written | envelope |
| Edit that makes Published invalid | clear title / last image | `400` listing every problem, nothing written | envelope |
| Edit Archived | any field incl. identity | saved (validated like a Draft) | N/A |
| Edit sold / rented / removed / restricted | owner | `403`, nothing written | envelope |
| Restricted or removed view | owner GET | shown with `restriction_reason`, not editable | N/A |
| Counts / filter | owner | per-status counts, filtered lists; other accounts isolated | N/A |
| Stale revision | old base | `409 stale_revision` + current | envelope |
| Other account / admin / Visitor | any | `404` / `404` / `401` | envelope |
