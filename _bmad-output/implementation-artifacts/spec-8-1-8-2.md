# Stories 8.1 and 8.2: Agency dashboard and listing view statistics (BE+FE)

Acceptance criteria: `epics.md`, Epic 8. Rules: FR-55, FR-56.

## API

| Route | Meaning |
|---|---|
| `GET /api/v1/me/agency-dashboard` | `total_listings`, `by_status`, `inquiries_total`, `views_total` |
| `GET /api/v1/me/agency-dashboard/listings?status&category&city_id&locality_id&created_from&created_to&cursor` | the filtered Listings with `views` and `inquiries`, 20 a page |
| `POST /api/v1/public/listings/{id}/views` | view beacon; `204` counted or not; `404` if not public |

Dashboard routes: Agency accounts only (Suspended may read); others `403`, Visitor `401`.

## Decisions

- Quota and remaining come from the existing `/me/publication-allowance` card; the inbox is `/messages`.
- An inquiry is a Conversation another account started about the Agency's Listing.
- The date filter is the Karachi date of creation, inclusive.
- Views: only a total per Listing, plus a 30-minute bucket keyed by an HMAC of Listing, client
  network and `User-Agent`, purged by `listings.view_buckets`. No cookie, no per-visitor record.
  "Session" therefore means "same browser on the same network".
- Not counted: owner, administrators, self-declared bots, empty `User-Agent`, over 300 an hour per
  network. Server renders and `GET` never count. Totals are indicative, not fraud-proof.
- Frontend: an agency section on `/dashboard`; a client beacon on the public detail page. UI polish
  deferred.
