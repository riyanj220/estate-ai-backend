## Intent

FR-12 deferred fields (addendum section 8): a Seller can state installment and legal details, and add a floor plan and a
video or virtual tour link. Registry-driven, validated, shown with "Seller-declared" where it is a claim, filterable where
searchable, public only on publicly visible Listings.

## What was built

- Registry version 12. Sale only: `payment_type`, `down_payment`, `total_installment_price`, `monthly_installment`,
  `remaining_installments`, `title_document_type`, `approval_information`, `approval_reference_number`,
  `mortgage_declaration`. Both purposes: `video_tour_url` (new type `url`).
- Storage: `ListingTerms.extra_attributes` (JSON, AD-4) for the nine sale fields; `PropertyListing.video_tour_url`;
  `ListingFloorPlan`. Migration `listings/0021`.
- `PUT` / `DELETE /api/v1/listings/{id}/floor-plan` (OWNER in `audience.py`); bytes served by the existing media endpoint.
- Owner, preview, public detail and administrator review carry `floor_plan`.
- Frontend: registry-built controls, floor plan section, floor plan and tour link on preview and public page; filters come
  from the registry unchanged. AI extraction schema version 4.

## Decisions

- No `installment_available`: `payment_type` says it. `ownership_document_type` and `title_document_type` are one field.
- All nine apply to every sale Listing (not only plots); all optional; no cross-field rule between payment fields.
- Filterable: `payment_type`, `title_document_type`, `mortgage_declaration` (no numeric filters over JSON).
- Title, approval and mortgage fields are `seller_declared` and not `ai_extractable`.
- None is a valuation input or quota identity, so no fingerprint migration, no re-estimate and no counted republication.
  Existing Listings keep their `registry_version` until their next write.
- One floor plan per Listing, in its own table: never a photo, cover, part of the 10-image limit or of `images_required`.
  Same editable statuses, storage cap and upload limit as images; removed wherever the Listing's images are removed
  (account closure keeps both, as before).
- Links: `https` and a named host only; no user part, port, IP, spaces or non-ASCII; chat hosts and contact details are
  refused. Never fetched, never embedded; the link is not put into AI text.

## Checklist (docs/story-checklist.md)

No account-existence, email-token or admin-guard surface is added. No new events or mail. The data migration rule does
not apply (schema only).

## Left out

Sample data (Story 11.1) does not fill the new fields. A report snapshot does not record the floor plan.
