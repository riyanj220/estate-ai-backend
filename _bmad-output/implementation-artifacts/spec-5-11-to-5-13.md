# Stories 5.11 to 5.13: nearby facilities and corrections, approval, description

Sources: `epics.md` Epic 5, FR-26, FR-27, FR-29, FR-30, AD-4, AD-8, AD-10. Builds on spec-5-9-5-10.

## API (additions)

- Session and turn result: `summary[{field, value, confirmed}]`, what the Listing holds now.
- `POST /api/v1/listings/{id}/confirm {base_revision, fields[]}`: `200` Listing; `409 stale_revision` / `conflict` (not a Draft); `400` for a bad list or an empty field.
- `POST /api/v1/assistant/sessions/{id}/description {base_revision, replace?}`: `200 {outcome, message, listing, claims[{text, fields}], left_out[]}`; `400 description` `manual_description` or `nothing_confirmed`; `409`; `429`.

## Decisions

- 5.11: the turn schema (version 3) adds `nearby[{facility, state}]` and `unmatched_nearby[]`. A facility is saved only if the message names it (a short synonym list, English and Roman Urdu). The amenities map is merged, never replaced by the model; a facility changed meanwhile is left alone. Unmatched words are repeated only if the message holds them. No distances: there is no field for one.
- 5.11: corrections are ordinary writes of the newest value. The "conversation summary" is `summary`, computed from the Draft, so it cannot go stale.
- 5.12: sensitive = Category, Subtype, purpose, asking price, locality, area value and unit. Publication now also refuses an unconfirmed AI asking price (the quota identity, city included, was already refused). Other unconfirmed AI values do not block (the story does not ask it). Purpose, Category and Subtype are chosen by the Seller at creation, so they count as confirmed.
- 5.12: confirmation sends field names only; the service re-saves the stored value with origin manual through `apply_updates`. An import contract stops `assistant` importing publication.
- 5.13: one model call; the model sees only confirmed public facts, as context data. Each sentence cites fact ids; code drops a sentence with no or unknown citation, a number, amenity or facility the cited values lack, a verification claim or contact details. Fewer than 2 paragraphs left: nothing is saved.
- 5.13: the text is saved as an unconfirmed AI value. A Seller-written (or confirmed) description needs `replace: true`. It shares the 30-an-hour assistant limit. The claim checklist is returned, not stored.
- Frontend: a review screen `/account/listings/{id}/review` (confirm values, generate, edit, then the existing publish page). Publication stays the Seller's own action.

## For later stories

- 5.14: turns replay their stored result; `summary` and `next_step` are recomputed. Description generation has no idempotency key: a repeat gets `409 stale_revision`, so it cannot write twice.
- 5.15: every failure of a turn or a generation leaves the Draft unchanged and returns an `outcome`.

## Checks and limits

`tests/assistant/test_approval.py` (includes the 30 scenarios), egress entry `assistant-description`, frontend `tests/e2e/assistant-review.spec.ts` (axe). The claim check cannot judge adjectives or negations; the Seller reviews. The 30 scenarios test the code's guards against a stub, not a real model's accuracy.
