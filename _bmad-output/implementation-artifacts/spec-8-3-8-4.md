# Stories 8.3 and 8.4: Agency Verification (BE+FE)

Acceptance criteria: `epics.md`, Epic 8. Rules: FR-57, FR-58, FR-62. Owner direction: a final-year
project can validate nothing, so Verification is a light formality.

## API

| Route | Meaning |
|---|---|
| `GET /api/v1/me/agency-verification` | own `status`, `can_submit`, `can_withdraw`, latest request |
| `POST /api/v1/me/agency-verification/requests` | `business_name`, `registration_number`, `note?`; `409` if pending or verified |
| `POST /api/v1/me/agency-verification/withdraw` | withdraw the pending request |
| `GET /api/v1/admin/verification-requests?status&cursor` | queue, oldest first, no private field |
| `POST .../{id}/read` `{reason}` | reasoned read: number, note, history |
| `POST .../{id}/approve`, `/reject` `{reason}`, `/revoke` `{reason}` | decide |

## Decisions

- `governance` owns requests and an append-only decision table; `identity` keeps only the public
  flag `unverified`/`verified`, changed by `identity.services.set_agency_verification` (AD-3).
- Statuses: `unverified` (derived), `pending`, `verified`, `rejected`, `revoked`, `withdrawn`. At
  most one pending request per Agency (database constraint and account lock).
- A Suspended Agency may read but not submit or withdraw, and cannot be approved. Email-unverified
  may do all of these. Reject and revoke are allowed whatever the state.
- Notifications (`verification.approved|rejected|revoked`) carry no payload; the reason is read on
  `/account/verification`.
- The public indicator is the existing `advertiser.verified` and Agency page `verified`; it is read
  live, so revocation removes it everywhere and Listings stay published.

## Departures

- **No supporting document** (8.3, OQ-3): no upload, storage or evidence route. The registration
  number and note stand in as the evidence: private, and read by an administrator only with a
  recorded, audited reason. "Another account requests the evidence" cannot arise: owner routes
  take no id.
- No rate limit on submit/withdraw (one pending at a time bounds the queue).
- Account deactivation does not yet withdraw a request or clear the flag (Epic 10 should).
- UI polish deferred.
