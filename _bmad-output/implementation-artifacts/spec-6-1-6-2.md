# Stories 6.1 and 6.2: natural-language search and its interpretation

Sources: `epics.md` Epic 6, FR-35, FR-36, AD-8, AD-25. Builds on the public filter (3.3) and the gateway (5.1 to 5.4).

## API

`POST /api/v1/public/search {query}` (public, CSRF token required, `no-store`) returns `200 {status, message, params, unsupported[], notices[]}`. `params` are query parameters of `GET /api/v1/public/listings`. `400` for a blank, over-500 or malformed body; `429` with `Retry-After`.

## Decisions

- The POST only interprets. Results come from the public list, so `search_public` stays the only query path, and editing a chip is an ordinary filtered read with no AI. The query text is never in a URL, stored or logged.
- The model reports what was asked (`search.interpretation.schema`, from the registry and amenity catalogue). Code does unit arithmetic, decides required or preferred, matches place names and validates every parameter with `catalog.filters.parse`.
- Required: purpose, Category, Subtype, city, locality, price bounds, area, bedroom or bathroom counts with a stated comparison, and anything marked must or need.
- Area is always required (FR-35: no marla basis means left out). Without a stated marla size the search spans 225 to 272.25 sq ft, and says so.
- A bare price is a maximum; a bare room count is exactly that many, as a preference; "parking" is at least one space. "Under N" rooms is at most N-1; "under" a price includes it.
- A locality name means the exact match, else every locality whose name starts with it ("DHA"). The same name in several cities means all of them. An unknown place is named as unsupported.
- Unsupported phrases are shown only if the buyer wrote them (redacted text).
- Fallback (`200`, `status: fallback`): AI off, provider error, timeout, budget, unusable answer, nothing recognised.
- Frontend: search box on `/listings`, only with `AI_FEATURES=1`, behind the external-service notice. The typed text is kept in `sessionStorage` across full page loads. Preferences now show as removable chips; a preference is changed by removing it and using the filter panel.
- "Provenance" on results is the card's existing advertiser and date; nearby facilities are labelled seller-declared in chips and notices.

## SM-3 and the labelled set

`apps/search/labelled_queries.yaml` (63 English queries with the correct model answer and expected filters). Tests replay the answers, so they check the code, not a model. `manage.py evaluate_search` asks the configured model and reports accuracy, rejected and repaired shares and p90 latency (one call per query, from the open budget). Each live search logs `search_interpretation_clean|repaired|rejected`.
