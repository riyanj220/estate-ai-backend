# Stories 6.3 and 6.4: voice search, search availability and abuse control

Sources: `epics.md` Epic 6, FR-37, FR-38, AD-8, AD-25. Builds on `spec-6-1-6-2-natural-language-search.md`.

## API

`POST /api/v1/public/search/transcription` (public, CSRF token, multipart with one part `audio`, `no-store`) returns
`200 {status: transcribed|fallback, transcript, message}`. `400` codes under `fields.audio` (empty, too large,
unaccepted type); `429` with `Retry-After`. The transcript is then sent to `POST /api/v1/public/search`.

## Decisions

- Counting: transcription has its own scopes (`ai_voice_visitor` 10 a minute, `ai_voice_account` 30 an hour). Only
  the text search of the confirmed transcript uses the search scopes, so one voice search counts once.
- Budget: a voice search is two provider requests (transcribe, interpret), both from the open half.
- Types: decided from the bytes. WebM, Ogg and WAV go as they are; MP4 goes as `audio/m4a`. Gemini accepts the
  browser containers (`docs/ai-providers.md`), so nothing is converted on the client.
- Size: 2 MiB (the gateway's cap, lowered from 5 MiB). The request body is capped before Django reads it, below the
  size at which it would spool to disk: audio stays in memory, is not stored and not logged. The client stops at
  30 seconds. Duration is not decoded on the server; the size cap bounds it.
- The transcript is returned to its speaker unredacted (their own words), cut to 500 characters, and redacted as any
  typed request when searched.
- Frontend: a microphone button beside the search box (so only with `AI_FEATURES=1`), the external-service notice
  first, `MediaRecorder` with WebM, then MP4, then Ogg. The transcript fills the text box and is never searched by
  itself. It stays there after the search. Without `MediaRecorder` or `getUserMedia` (including plain HTTP on a
  phone) the button is absent and the text box is offered. Browser speech recognition is not used.
- `Permissions-Policy`: the API's `microphone=()` applies to API responses only; the frontend sends no such policy,
  and a test asserts the browse page does not block the microphone. A deployment proxy must not add one.
- 6.4: the limits, 429 envelope, reserved budget, 12 second timeouts and flag fallback came with 6.1; added here are
  the voice path of each and tests of the reservation under many callers and concurrent counting.

## Checks and limits

`tests/api/test_voice_search_api.py`, `tests/search/test_audio_and_wer.py`, egress entry `voice-search`, smoke flow
"search by description", frontend `tests/e2e/voice-search.spec.ts` (mocked microphone and recorder, axe).

Not measured: p90 against the 10 second target (three real transcriptions took 1.4 to 1.9 s; no volume run, and
interpretation latency is as unmeasured as in 6.1), word error rate on human English, any Urdu or Roman Urdu speech,
and a real phone or Safari.
