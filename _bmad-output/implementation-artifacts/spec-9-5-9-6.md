# Stories 9.5 and 9.6: Conversation Reports and Listing flags (BE+FE)

Acceptance criteria: `epics.md`, Epic 9. Rules: FR-54, FR-66, AD-9, AD-23. Owner direction: a final-year project; keep
governance simple; fixed deterministic rules, no ML.

## API

| Route | Meaning |
|---|---|
| `POST /api/v1/conversations/{id}/reports` | `message_ids` (1 to 10), `reason`, `description?`; participants only (404), Suspended 403, 409 already open, 429 shares the 10 a day |
| `GET /api/v1/admin/reports...` | rows and detail gain `target_type`; a Conversation Report carries no Messages or description |
| `POST /api/v1/admin/reports/{id}/read` `{reason}` | the reasoned, audited read of the snapshot and description |
| `GET /api/v1/admin/flags?kind&cursor` | advisory flags, newest first |

## Decisions (9.5)

- Only the other participant's Messages can be selected. The snapshot (taken through
  `messaging.selectors.report_evidence`) holds them plus up to 5 sent just before the earliest selected one; no names
  or account ids. Unselected Messages between two selected ones are not copied.
- One open Report per reporter per Conversation. Private target `report_snapshot`.
- The description is treated as private too (it may quote Messages).
- Anonymisation: the deactivated side is labelled `deleted_user` and phone numbers, email addresses and addresses are
  removed from all snapshot text and the description. Bodies are otherwise kept, as Messages themselves are. Runs on
  `account.session_ended` (`deactivated`), repaired by retention job `governance.report_snapshots`, and at submission
  if the other account is already Deactivated. No deactivation route exists yet: the Epic 10 deactivation use case
  (AD-23) should call `governance.reports.anonymise_participant` inside its own transaction.
- "Optionally followed by a suspension" uses the existing account suspension page; resolving never suspends by itself.
  No route edits or deletes a Message.

## Decisions (9.6)

- `governance.ListingFlag` is derived data: each run adds what holds and removes what no longer does. No dismiss or
  workflow.
- Duplicate: Published Listings of one owner with the same purpose, category, locality and area (square feet), and a
  price within 2% or a normalised title at least 90% alike. One row per pair, named by the newer Listing.
- Suspicious: open Listing Reports from two different reporters made within 7 days of each other. Evaluated by the
  nightly run only.
- `manage.py run_flags` (schedule nightly); the duplicate rule also runs on `listing.published`; `listing.deleted`
  drops that Listing's flags. The price estimate is not used (the criteria do not ask for it).

## Operating note

After pulling: `uv run python manage.py migrate --database=migrator` (one new ordinary table; the post-migrate hook
grants it, no append-only change). Then `uv run python manage.py run_flags` to fill the flag list.
