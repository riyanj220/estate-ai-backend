# Stories 10.4 to 10.8: account review, reference data, AI oversight, audit review, dashboard (BE+FE)

Acceptance criteria: `epics.md`, Epic 10. Rules: FR-61, FR-67 to FR-70. Owner direction: a final-year project; plain
screens (the UI is redesigned later). Constraints: `docs/story-checklist.md` (admin guard on every page, neutral
titles).

## API (all administrator only, never cached)

| Route | Meaning |
|---|---|
| `GET /api/v1/admin/accounts?q&type&state&cursor` | directory: name, masked email, type, state |
| `GET /api/v1/admin/accounts/{id}` | profile, Reports about it, closure requests |
| `POST /api/v1/admin/accounts/{id}/private` `{reason}` | email, phone, office address |
| `POST /api/v1/admin/listings/{id}/private-address` `{reason}` | one Listing's Private address |
| `GET, POST /api/v1/admin/reference/cities`, `PATCH .../cities/{id}` | name, `is_active` |
| `GET, POST .../cities/{id}/localities`, `PATCH .../localities/{id}` | areas and societies |
| `GET, POST .../reference/amenities`, `PATCH .../amenities/{code}` | amenities and nearby facilities |
| `GET .../reference/fixed` | purposes, Categories, Subtypes, area units (read only) |
| `GET /api/v1/admin/ai-oversight`, `POST .../switches/{name}` `{enabled}` | status, 7-day counts, model |
| `GET /api/v1/admin/audit-records?actor&action&target_type&target&date_from&date_to&cursor` | read only |
| `GET /api/v1/admin/dashboard` | counts taken at load |

Screens: `/admin` (dashboard), `/admin/accounts` (directory above the email lookup), `/admin/accounts/[id]`,
`/admin/reference`, `/admin/ai`, `/admin/audit`; the admin Listing page gained the private-address read.

## Decisions

- The directory searches names and account ids, not email (the reasoned email lookup of 2.21 stays). Emails are
  masked everywhere until a reasoned read. New private targets: `account_contact`, `listing_address`.
- The account's Listings come from the existing admin Listing list with `owner` (newest 20 on the review screen).
- Reference items are never deleted, only deactivated (so "in use" needs no check) and can be reactivated. An amenity's
  code never changes. Audit metadata says what changed, not the name.
- Renaming a locality the price model covers stops its estimates until retraining (the model uses names).
- AI switches are rows of the existing `FeatureFlag` table, read on every request: a master `ai_gateway`, one per
  gateway feature (`ai_assistant_turn`, `ai_listing_description`, `ai_search_query`, `ai_voice_search`) and
  `price_estimate`. Off answers like an unavailable feature. With `price_estimate` off nothing is computed and stored
  figures are hidden too. Setting the same state again records nothing.
- The audit list of FR-69 was already covered by earlier stories; 10.5 and 10.6 add the reference and AI actions.
  Purging stays with Story 10.13.
- Dashboard account totals include every state; "new" and activity mean the last 7 days; unresolved Reports are
  pending plus reviewing.
- No new tables or migrations, so no new grants.

## Left over

- Audit details show ids; there is no link from a record to its target.
- AI counts depend on the AI request log, which keeps 90 days.
